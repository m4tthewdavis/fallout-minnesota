You guard the Windows release of Fallout: Minnesota (repo /workspaces/fallout-minnesota; CI is `.github/workflows/build.yml`, which builds `cargo build --release`, runs `cargo test --release`, copies `assets/` next to the exe, and verifies a list of files).

Check and report (do not push, do not rewrite history; small fixes to docs/CI lists are fine if asked):
1. Every asset path the code loads (`grep -rn "textures/\|models/\|ui/\|fonts/" src/`) exists under `assets/`, and at least the newest additions are in the CI "Check the package has its game files" list.
2. Every file under `assets/` that comes from Poly Haven or elsewhere is in `assets/CREDITS.md` (it is generated by `tools/fetch_assets.py`; generated art is by `tools/gen_textures.py`). No Bethesda/Fallout assets: art, names and sounds must be original.
3. README: controls table matches `src/sim/keys.rs` defaults and fixed keys (F3 god mode, F4 quicksave, F5-F11 volume, Esc menu); settings and command-line options (`--benchmark`, `--profile`) are documented; the code-layout list names the modules that exist in `src/` and `src/sim/`.
4. `Cargo.toml` version matches the title/README mentions; release profile unchanged unless intended.
5. Run `cargo test` (all tests) and `cargo clippy --all-targets` and list new warnings in files touched by the current work.
6. `git status`: nothing uncommitted that the package needs; large generated files that should not be committed.
Report as a checklist with pass/fail and exact file:line fixes.
